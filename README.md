# cursor-claude-workflow-kr

**1인 AI 스튜디오 [세라윤(SERAYUN)](https://serayun.com)에서 실제로 활용하는 AI 협업 개발 과정을 정리한 저장소입니다.**

Claude로 작업 지시서를 작성하고, Cursor·Codex·Gemini로 구현한 뒤, 다시 Claude와 함께 결과를 검토하는 방식으로 개발하고 있습니다.

복잡한 개발 체계를 구축하기보다는 **작업을 명확하게 정의하고, 구현하고, 검증하는 과정**에 집중합니다.

## 작업 흐름

### 1. 작업 정리 — Claude

구현하고 싶은 기능이나 개선할 부분을 Claude와 논의합니다.

목표와 요구사항을 구체화하고, 개발 도구가 바로 활용할 수 있는 작업 지시서로 정리합니다.

### 2. 구현 — Cursor · Codex · Gemini

작성한 작업 지시서를 개발 도구에 전달해 실제 구현을 진행합니다.

작업 범위와 완료 조건이 명확할수록 불필요한 수정과 반복 작업을 줄일 수 있습니다.

### 3. 검토 — Claude

구현 결과와 변경 사항, 해결되지 않은 문제를 Claude와 검토합니다.

필요한 경우 개선 방향을 정리하고 후속 작업 지시서를 작성합니다.

단순한 수정에 불필요한 전체 테스트를 반복하지 않고, 변경 사항의 영향과 위험에 맞춰 검증합니다.

### 4. 기록

작업 중 발생한 문제와 해결 방법, 확인된 결과를 `logs/`에 간단히 기록합니다.

이미 검증한 내용을 반복해서 조사하지 않도록 필요한 정보만 남깁니다.

## 작업 지시서 템플릿

- [`templates/work-order.md`](templates/work-order.md) — 목표, 작업 범위, 완료 조건, 검증 방법을 정리하는 작업 지시서 양식

## 운영 원칙

- **한 번에 하나의 작업에 집중합니다.** 작업 범위를 명확히 하고 불필요한 기능 확장을 피합니다.
- **완료 기준을 먼저 정합니다.** 무엇을 구현하고 어떻게 확인할지 명시합니다.
- **변경 범위에 맞춰 검증합니다.** 작은 수정에 전체 프로젝트 재검증을 반복하지 않습니다.
- **기존 작업과 기록을 활용합니다.** 불필요한 재조사와 중복 작업을 줄입니다.
- **실제로 확인한 결과만 기록합니다.** 계획, 구현, 테스트, 운영 적용을 구분합니다.
